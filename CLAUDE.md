# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Ani-Mangalist — a static PWA to track watched animes and read mangas. No build system, no npm, no framework. Plain HTML/CSS/JS served statically.

## Running the App

Open `index.html` directly in a browser, or serve with any static file server (e.g., `npx serve .` or VS Code Live Server). There are no build steps.

## Architecture

### Pages and Routing

| File | Purpose |
|---|---|
| `index.html` | Anime list, sourced only from MyAnimeList (`dados/mal.json`) |
| `manga.html` | Manga list (`dados/mangas.json`, generated by `scripts/import-mangas.mjs`) |
| `detalhe.html` | Detail view shared by both; receives `?id=X&tipo=anime\|manga` via URL params (`tipo=mal` still accepted as anime) |

Both list pages share `js/index.js`; `<body data-tipo="anime|manga">` picks the JSON. It renders a cover grid grouped into status "halls" with search and status chips. Visual system is documented in `DESIGN.md`.

There is no hand-kept anime list: animes are added/changed on MyAnimeList only. `dados/mal.json` is generated by `scripts/fetch-mal.mjs` (MAL public `load.json` endpoint, no CORS so it can't be fetched from the browser) and refreshed daily by `.github/workflows/mal.yml`. Do not edit it by hand; its `Id` is the MAL anime id.

The detail page fetches the appropriate JSON based on `tipo`, finds the entry by `Id`, and renders it inline via a `<script>` block inside `detalhe.html`.

### Data Layer

All data lives in `dados/`:

- `dados/mal.json` — anime entries generated from MAL; never edit by hand
- `dados/mangas.json` — manga entries; regenerate with `node scripts/import-mangas.mjs <export.txt>` (tracker export: `### Reading` / `# Title` / MAL, AniList, MangaUpdates links). The script enriches from AniList/MangaUpdates and preserves `cap` and entries missing from the export. `total` must equal array length.

**Anime entry schema** (`mal.json`):
```json
{ "Id": 58516, "Nome_jp": "...", "Nome_eng": "...", "Status": "Assistindo", "Image": "https://...", "ep": 3, "eps": 12, "score": 0 }
```
Anime statuses: `"Completo"`, `"Assistindo"`, `"Em Pausa"`, `"Pretendo Assistir"`, `"Dropado"`.

**Manga entry schema:**
```json
{ "Id": 93, "Nome_jp": "...", "Nome_eng": "...", "Status": "Lendo", "Image": "https://...", "cap": 42, "caps": 120, "mal": 1, "anilist": 1, "mangaupdates": "abc123" }
```
Manga statuses: `"Lendo"`, `"Completo"`, `"Pretendo Ler"`, `"Dropado"`, `"Em Pausa"`.

### ID Convention (mangas.json)

IDs are assigned sequentially (descending in the file — newest entry has the highest Id and appears first). When adding a new entry, increment `total` and use `total` as the new `Id`.

### PWA

`manifest.json` and `sw.js` wire up the PWA. No special handling needed when editing data files.

# RTK (Rust Token Killer) - Token-Optimized Commands

## Golden Rule

**Always prefix commands with `rtk`**. If RTK has a dedicated filter, it uses it. If not, it passes through unchanged. This means RTK is always safe to use.

**Important**: Even in command chains with `&&`, use `rtk`:
```bash
# ❌ Wrong
git add . && git commit -m "msg" && git push

# ✅ Correct
rtk git add . && rtk git commit -m "msg" && rtk git push
```
